## 1. 整体链路

```
用户请求
  ↓
【召回 Recall】 亿级 → 千级    多路召回，注重覆盖率，追求 Recall
  ↓
【粗排 Pre-rank】 千级 → 百级   轻量模型，算力约束下的打分
  ↓
【精排 Rank】 百级 → 几十       复杂模型，全特征，追求 AUC
  ↓
【重排 Re-rank】                 打散、多样性、业务规则、上下文感知
  ↓
返回结果
```

**Q：为什么要分这么多阶段？（必答）**
算力与效果的权衡。精排模型的单次打分成本是召回的几个数量级，不可能对亿级候选全打分。用**漏斗结构**，每一层用与候选量匹配的复杂度：召回快而糙保证覆盖，精排慢而准保证质量。

**Q：粗排的特殊之处？**
粗排面临**样本选择偏差**（训练数据来自精排结果，但线上要打分的是召回的全集）和**一致性问题**（粗排排序和精排排序不一致会导致精排拿不到好候选）。解法：粗排蒸馏精排（用精排打分当软标签）、加入随机负样本、COLD 那样的"算力-效果联合设计"。

## 2. 召回

### 2.1 多路召回

典型路数：
- **协同过滤类**：ItemCF（"看了又看"，可解释性强，实时性好）、UserCF、Swing、Item2Vec。
- **向量召回**：双塔 DSSM、YouTube DNN。
- **内容/标签召回**：类目、标签、关键词倒排。
- **热门/新品召回**：兜底 + 探索。
- **图召回**：GraphSAGE、PinSage、EGES。
- **序列召回**：SASRec、MIND（多兴趣）。

各路截断后取并集送入粗排。多路是为了**互补**，单路模型很难同时保证相关性、多样性、时效性。

### 2.2 双塔模型（DSSM）

用户塔和物品塔分别编码成向量，用内积/余弦算相似度。物品向量**离线预计算**存入 ANN 索引（Faiss/HNSW），线上只算用户塔 + ANN 检索，毫秒级。

**Q：双塔最大的缺点？（必问）**
用户特征和物品特征**只在最后一层做内积交互**，无法做早期特征交叉（比如"用户年龄 × 物品品类"这种关键交叉信号学不到）。这是为了工程上能预计算物品向量而付出的代价。

**改进方向**：
- **SENet 双塔**：在塔内对特征做重要性加权，抑制噪声特征。
- **多目标/多兴趣双塔**：用户侧输出多个向量（MIND 用胶囊网络，ComiRec 用注意力），召回时每个兴趣各取 top-k。
- **交互增强**：塔顶加轻量交互层（但会牺牲预计算能力）；或用蒸馏把单塔的知识传给双塔。
- **对比学习**：加入 in-batch negatives + 自监督任务缓解长尾。

### 2.3 负采样（高频且容易答错）

**核心认知：召回和排序的样本空间不同。**
- **排序**的负样本 = 曝光未点击（因为线上排序面对的就是召回来的候选，都是"还不错"的）。
- **召回**如果只用曝光未点击当负样本，会导致**样本选择偏差** —— 线上召回面对的是全库物品，其中绝大多数是"完全不相关"的，模型没见过这类样本就分不出来。

**召回的负采样方式**：
| 方式 | 说明 |
|---|---|
| **随机负采样** | 从全库随机抽，是召回的主力负样本 |
| **Batch 内负采样** | 同 batch 内其他样本的正例当负例，高效；但有**热门物品打压过度**问题，需要 **LogQ 校正**：$s' = s - \log p_{item}$〔Yi et al., RecSys 2019〕 |
| **Hard Negative** | 排名靠前但未点击的，提升区分度；比例不宜过高（easy:hard 量级约 100:1，**经验值，各家差异大**） |
| 曝光未点击 | 可以少量混入，但不能作为主体 |

**Q：为什么要做 LogQ 校正？** Batch 内采样时热门物品被采为负样本的概率高，模型会过度打压热门物品，破坏了原本的物品流行度分布。减去 $\log p$ 做重要性纠偏。

### 2.4 图召回与 GNN

**为什么要上图？** 用户-物品交互天然是一张二部图。ItemCF 只用到**一阶邻居**（共现），
而"我喜欢的物品的相似用户还喜欢什么"是二阶、三阶信息。GNN 的价值就是**把高阶邻居的信息聚合进节点表示**。

**核心操作（消息传递）**：第 $k$ 层
$$h_v^{(k)}=\sigma\left(W^{(k)}\cdot\text{AGG}\left(\{h_u^{(k-1)}:u\in\mathcal{N}(v)\}\cup\{h_v^{(k-1)}\}\right)\right)$$
堆 $k$ 层就聚合到 $k$ 跳邻居。

| 模型 | 关键点 |
|---|---|
| **GCN** | 用归一化邻接矩阵 $\tilde D^{-1/2}\tilde A\tilde D^{-1/2}$ 做全图聚合。**直推式（transductive）**：训练时要看到全图，新节点来了必须重训 |
| **GraphSAGE** | ① **采样固定数量邻居**（不用全图，可 minibatch）；② 可插拔的聚合函数（mean / pool / LSTM）。**归纳式（inductive）**：学的是聚合函数而不是每个节点的向量，**新节点直接能算出表示** —— 这是工业推荐的刚需 |
| **PinSage** | GraphSAGE 的工业化：用随机游走的访问频次做**重要性采样**邻居（而不是均匀采样），配合生产者-消费者式 minibatch，跑到 30 亿节点规模〔PinSage, KDD 2018〕 |
| **LightGCN** | **砍掉特征变换和非线性激活**，只保留邻居聚合与各层加权求和，在推荐场景反而更好〔LightGCN, SIGIR 2020〕 |
| **EGES** | 阿里：在 item2vec 的图游走上融合类目/品牌等 side information，主要解决**冷启动**（新物品没有共现但有属性） |

**Q：为什么 LightGCN 把 MLP 砍掉效果反而更好？（高频追问）**
GCN 最初是为**带语义节点特征**的图（如论文的词袋特征）设计的，那里非线性变换有用。
但推荐场景的节点输入是**随机初始化的 ID Embedding，本身没有语义**，
再叠特征变换只是增加了参数量和过拟合风险，聚合本身（邻居平滑）才是有效成分。
**这个例子很值得记：不是模型越复杂越好，要看归纳偏置和数据形态匹不匹配。**

**Q：GNN 层数为什么一般只有 2-3 层？**
**过平滑（over-smoothing）**：层数越深，聚合范围越大，所有节点的表示趋于一致，区分度反而下降。
另外每加一层邻居数指数增长，计算和采样成本都爆炸。

**工业落地的现实**：GNN 召回的收益通常来自"补充了长尾和冷启的关联"，
而不是全面超过双塔。多数团队把它作为**多路召回中的一路**，不是替代品。

## 3. 排序模型演进（必背这条线）

理解**每一步在解决上一步的什么问题**，比记住模型名字重要得多。

| 阶段 | 模型 | 解决的问题 |
|---|---|---|
| 线性 | **LR + 人工特征** | 简单、可解释、能上大规模；但**特征交叉全靠人工** |
| 自动二阶交叉 | **FM** | 用 $\langle v_i,v_j\rangle$ 代替 $w_{ij}$，解决稀疏数据下交叉项学不到的问题 |
| | **FFM** | 每个特征对不同 field 有不同向量，表达更强但参数量爆炸 |
| 树 + 线性 | **GBDT + LR** | 用树自动做特征组合，叶子节点当离散特征喂 LR |
| 记忆 + 泛化 | **Wide & Deep** | Wide 部分记忆（人工交叉，强规则），Deep 部分泛化（Embedding+MLP） |
| 自动化 wide | **DeepFM** | 用 FM 替代 Wide，**免去人工特征工程**，且共享 Embedding |
| 显式高阶交叉 | **DCN / DCN-V2** | Cross Network 显式做有界阶数的特征交叉，参数量低 |
| | **xDeepFM** | CIN 在 vector-wise 层面做显式高阶交叉 |
| 用户行为建模 | **DIN** | **用注意力让用户历史行为对不同候选物品有不同的权重** |
| 序列演化 | **DIEN** | GRU + AUGRU 建模兴趣演化 |
| 长序列 | **SIM / ETA** | 两阶段：先用类目/哈希检索(GSU)从千级历史里筛出相关的，再做注意力(ESU) |
| 多目标 | **MMoE / PLE** | 多个任务共享底层但各有门控专家 |

### 3.1 FM 的关键推导

$$\hat y = w_0+\sum_i w_ix_i+\sum_{i<j}\langle v_i,v_j\rangle x_ix_j$$

朴素计算二阶项是 $O(kn^2)$，化简后是 $O(kn)$：
$$\sum_{i<j}\langle v_i,v_j\rangle x_ix_j=\frac12\sum_{f=1}^{k}\left[\left(\sum_i v_{i,f}x_i\right)^2-\sum_i v_{i,f}^2x_i^2\right]$$

**这个化简是 FM 面试的经典考点，要能写出来。**（"和的平方减平方的和"）

**Q：FM 相比 LR 的多项式模型好在哪？**
多项式模型的 $w_{ij}$ 只有当 $x_i,x_j$ **同时非零**时才有梯度，在稀疏数据下绝大多数组合从未共现，学不到。FM 把 $w_{ij}$ 分解成 $\langle v_i,v_j\rangle$，$v_i$ 可以从所有含 $x_i$ 的样本中学习，**实现了泛化**。

### 3.2 DIN 的核心

用户历史行为序列 $\{e_1,...,e_H\}$ 对候选物品 $e_a$ 做注意力：
$$v_U(a)=\sum_{j=1}^{H}a(e_j,e_a)\,e_j$$

**动机**：用户兴趣是多样的，但对某个候选物品只有部分历史行为相关。给"看过的游戏本"打分时，历史里的"键盘鼠标"应该权重高，"奶粉"应该权重低。**固定的用户向量（sum/avg pooling）表达不了这种依赖候选的兴趣。**

细节：DIN 的注意力**不做 softmax 归一化**，保留激活强度（反映兴趣强度）；还提出了 Dice 激活和自适应正则。

### 3.3 多目标：MMoE 与 PLE

**动机**：推荐要同时优化点击、时长、点赞、转化等多个目标，单独建模成本高且无法共享信息。

- **Shared-Bottom**：底层完全共享 → 任务冲突时互相拖累（**跷跷板效应**）。
- **MMoE**：多个专家 + **每个任务一个 gate** 决定怎么加权专家。任务相关性低时也能通过 gate 分化。
- **PLE**：显式区分**任务专属专家**和**共享专家**，并做多层渐进抽取，进一步缓解跷跷板。

**Q：多目标的分数怎么融合？**
常用加权乘法：$\text{score}=p_{ctr}^{\alpha}\times p_{cvr}^{\beta}\times (\text{时长})^{\gamma}$。指数形式便于调节各目标影响力，权重靠线上 A/B 调。也可用帕累托优化或直接学融合参数。

### 3.4 ESMM（转化率建模，高频）

**CVR 建模的两个问题**：
1. **样本选择偏差 (SSB)**：CVR 模型在"点击"样本上训练，但线上要在"曝光"空间打分。
2. **数据稀疏**：点击样本远少于曝光样本。

**ESMM 的解法**：在**全曝光空间**训练两个辅助任务
$$\underbrace{p(y=1,z=1|x)}_{\text{CTCVR}} = \underbrace{p(y=1|x)}_{\text{CTR}}\times \underbrace{p(z=1|y=1,x)}_{\text{CVR}}$$
直接监督 CTR 和 CTCVR（都在曝光空间有标签），CVR 作为中间变量被隐式学习。同时两个塔共享 Embedding 缓解稀疏。

## 4. 特征工程

### 4.1 特征体系

| 类别 | 例子 |
|---|---|
| 用户侧 | 人口属性、长期兴趣画像、短期行为序列、活跃度 |
| 物品侧 | ID、类目、标签、内容 Embedding、作者 |
| 上下文 | 时间、地点、设备、网络、场景/页面 |
| 统计交叉 | 用户对该类目的历史 CTR、物品在该人群的 CTR（**必须用时间窗口，且严禁用未来数据**） |
| 匹配特征 | 用户画像与物品标签的重合度/相似度 |

### 4.2 Embedding

**Q：高基数 ID 特征（上亿 item ID）怎么处理？**
- **Hash 到固定桶**：省内存但有冲突。双哈希（Hash Trick + Compositional Embedding）可缓解。
- **动态 Embedding / 参数服务器**：工业界主流，只为出现过的 ID 分配空间，配合准入（出现次数 > 阈值才建 Embedding）和淘汰（长期不活跃就删）策略。
- **低频 ID 聚合**：低频 item 用其类目/标签的 Embedding 代替。

**Q：Embedding 维度怎么定？** 经验公式 $d\approx 6\sqrt[4]{n}$ 或 $d=\lceil\log_2 n\rceil$ 附近；实践中按特征重要性分配（重要特征给 32/64，长尾特征给 8/16）。

**Q：Embedding 层为什么是模型的绝大部分参数？** 亿级 ID × 数十维，占 90%+ 参数量，训练时是通信瓶颈，所以有专门的参数服务器架构和稀疏优化器（Adagrad 对稀疏特征友好）。

### 4.3 特征穿越（严重问题）

统计类特征必须严格按事件时间窗口计算。例如"item 近 1 小时 CTR"，训练时如果用了包含当前样本自身的统计，就把标签泄漏进特征了 → 离线 AUC 虚高、线上暴跌。
解法：用**流式特征快照** —— 线上打分时把用到的特征原样落盘，训练直接用这份快照，从根本上保证训练/推理一致。

## 5. 冷启动

| 类型 | 解法 |
|---|---|
| **新用户** | 注册信息 + 设备 + 地域做粗粒度画像；热门/高质量内容兜底；**快速试探**（前几刷给多样化内容快速探明兴趣）；用同人群的行为做迁移 |
| **新物品** | 用内容特征（标题/图像/视频的多模态 Embedding）代替 ID Embedding；给流量扶持池（保量投放）；ID Embedding 用内容 Embedding 初始化（**Cold-start warm-up**） |
| **新场景/新域** | 跨域推荐、迁移学习 |

**探索利用（E&E）**：$\epsilon$-greedy（简单粗暴）、UCB（$\bar x + c\sqrt{\frac{\ln t}{n}}$，不确定性加成）、**Thompson Sampling**（Beta 后验采样，工业界常用，天然处理延迟反馈）、LinUCB（带上下文特征）。

## 6. 评估与实验

### 6.1 离线指标

- **AUC**：整体排序能力。
- **GAUC**（必答）：按用户分组算 AUC，再按曝光数/点击数加权平均。
  **为什么需要？** 推荐是"给同一个用户的候选排序"，跨用户比较分数没有意义。有的模型只是学会了"活跃用户点得多"就能拿到高 AUC，但用户内部排序很差。GAUC 才反映真实体验。
- **NDCG / MAP / HitRate@K / Recall@K**：召回和排序的 topK 质量。
- **LogLoss / COPC**：$\text{COPC}=\frac{\sum\text{预估 CTR}}{\sum\text{真实点击}}$，衡量**校准**。广告必看（出价直接依赖绝对概率）。
- **Coverage / 基尼系数**：多样性和马太效应。

### 6.2 在线指标

CTR、CVR、人均时长、留存（次留/7 留）、GMV、ARPU、人均消费条数、多样性、生态指标（创作者侧）。

**Q：离线 AUC 涨了，线上不涨甚至跌，为什么？（超高频）**
1. **离线评估的样本空间和线上不一致**（离线是曝光样本，线上要面对召回全集）。
2. **特征穿越**导致离线虚高。
3. **AUC 只看排序不看校准**，广告场景校准变差会直接掉收入。
4. **线上有其他模块**：重排规则、多样性打散、流量分配把模型效果稀释了。
5. **模型的提升集中在低价值样本上**（比如提升了曝光位靠后的排序，用户根本看不到）。
6. **反馈延迟/数据分布漂移**，训练数据和线上流量分布不同。
7. **AB 实验本身有问题**：分桶不均、流量互相干扰、观察期太短、新奇效应。

### 6.3 A/B 测试

- **分层分流**：不同层之间正交（用不同的哈希种子），同层内互斥。这样多个实验可以同时跑。
- **AA 测试**：先跑空白对照验证分桶无偏。
- **注意**：新奇效应（新功能初期指标虚高）、学习效应（模型需要时间收敛）、网络效应（社交场景用户互相影响，需要按社群分流）。
- **反转实验/长期实验**：验证长期收益是否可持续。

### 6.4 位置偏置（Position Bias）

用户点击高位物品的概率天然高，训练数据中包含了这个偏置。

**解法**：
1. **PAL / Position as Feature**：训练时把位置作为一个独立特征（或独立的 shallow tower）输入，预测 $p(\text{click}) = p(\text{seen}|\text{pos})\times p(\text{click}|\text{seen})$；**线上预测时把位置置为固定值（如 0 或 1）**，从而剥离位置影响。
2. **IPW（逆倾向加权）**：样本权重除以该位置的观察概率。
3. 随机化流量估计位置倾向分。

## 7. 重排与多样性

精排给出的是逐条最优，但列表整体体验还要考虑多样性、疲劳度、上下文互相影响。

- **MMR**：$\arg\max_i [\lambda\, \text{rel}(i) - (1-\lambda)\max_{j\in S}\text{sim}(i,j)]$，贪心地在相关性和多样性间权衡。
- **DPP（行列式点过程）**：用核矩阵的行列式度量集合的"体积"（多样性），贪心最大化，比 MMR 效果好。
- **上下文感知重排**：PRM/miniBERT 对候选列表做自注意力，建模物品之间的相互影响。
- **业务规则**：同作者/同类目打散、广告与自然结果的混排、已读过滤、时效性加权。

## 8. 广告特有

- **计费方式**：CPM（按曝光）、CPC（按点击）、CPA（按转化）、oCPC/oCPM（**按转化优化但按点击/曝光计费**，平台承担预估风险）。
- **ECPM 排序**：$\text{ECPM}=\text{bid}\times\text{pCTR}\times\text{pCVR}\times1000$。所以 **pCTR 的校准比排序更重要** —— 排序错了只是位置不对，校准错了直接影响计费和 ROI。
- **GSP 拍卖**：广义第二价格。赢家付的不是自己的出价，而是**维持当前位次所需的最低价** —— 按 ECPM 排序时即 $\text{price}_i=\frac{\text{ECPM}_{i+1}}{\text{pCTR}_i}$（再加一个最小increment）。常被简述成「付第二名的出价」，只在各家 pCTR 相同时才等价，**面试时说准确口径会加分**。
  GSP 只是近似激励兼容（说真话不一定是严格最优策略）；VCG 严格激励兼容但计价难解释、广告主难接受，所以工业界仍以 GSP 为主。
- **智能出价**：给定预算和 ROI 约束下的出价策略，本质是带约束的最优控制（PID/强化学习）。
- **预算平滑（Pacing）**：防止预算在早上就花光，按小时流量分布控制投放速度。
- **延迟反馈**：转化可能在点击后几天才发生，训练时标签不确定。解法：延迟反馈建模（假设转化时延服从指数分布，做重要性加权）、多次回流校正。

## 9. 搜索特有（章名里的"搜索"在这里）

前面 1–7 节的链路、特征、多目标、评估在搜索里同样成立。这一节只讲**搜索与推荐的差异**。

### 9.1 本质差异

| | 推荐 | 搜索 |
|---|---|---|
| 用户意图 | 隐式，要猜 | **显式，写在 query 里** |
| 相关性 | 软约束（推了不感兴趣的只是体验差） | **硬约束**（返回不相关结果是事故，先过相关性门槛再谈个性化） |
| 核心匹配 | user × item | **query × doc** + user × item |
| 主要难点 | 兴趣建模、冷启动 | query 理解、语义鸿沟、长尾 query |

**一句话**：推荐是"我猜你喜欢"，搜索是"你说了我得给对" —— **相关性优先于个性化**，这个优先级说反了就是外行。

### 9.2 链路

```
query → query 理解（纠错 / 归一化 / 分词 / term weighting / 意图识别 / 改写扩展）
      → 召回（倒排 BM25 + 向量语义召回，多路并集）
      → 相关性排序（保证"对不对"）
      → 业务排序（点击率、质量、时效、个性化，决定"排多前"）
      → 重排（多样性、去重、混排）
```

**query 理解是搜索独有且最容易被追问的一环**：
- **纠错**：拼写/同音错误（"苹果肾" → "iPhone"），用编辑距离 + 混淆集 + 点击日志挖掘。
- **term weighting**：query 里的词不等权。"红色 连衣裙" 中"连衣裙"是核心词，删了就跑题；"红色"是修饰词，可放宽。
- **意图识别**：导航型（找官网）/ 信息型（找知识）/ 交易型（要买东西），意图不同排序策略完全不同。
- **改写与扩展**：同义词（"笔记本" ↔ "笔电"）、上下位词、query 补全。**风险是改写过度导致漂移**，一般要限制改写后的召回不能挤掉原 query 的结果。

### 9.3 BM25（必须会写）

$$\text{score}(D,Q)=\sum_{q_i\in Q}\text{IDF}(q_i)\cdot\frac{f(q_i,D)\cdot(k_1+1)}{f(q_i,D)+k_1\cdot\left(1-b+b\cdot\frac{|D|}{\text{avgdl}}\right)}$$

其中 $\text{IDF}(q_i)=\ln\left(\frac{N-n(q_i)+0.5}{n(q_i)+0.5}+1\right)$，常用 $k_1\in[1.2,2.0]$、$b=0.75$。

**要能解释每一项在干什么**：
- $k_1$ 控制**词频饱和**：出现 10 次不该是出现 1 次的 10 倍分，$\frac{f(k_1+1)}{f+k_1}$ 是一条趋于饱和的曲线。这是 BM25 优于朴素 TF-IDF 的关键。
- $b$ 控制**文档长度归一化**：长文档天然词频高，用 $|D|/\text{avgdl}$ 惩罚；$b=0$ 完全不惩罚，$b=1$ 完全归一化。
- IDF 压低"的、了"这类到处都出现的词。

### 9.4 语义鸿沟与混合检索

BM25 是**字面匹配**，「怎么让头发不掉」和「防脱发方法」一个词都不重合但意思相同 —— 这就是**语义鸿沟**。

- **向量召回补语义**，BM25 补**精确匹配**（型号 "iPhone 15 Pro Max"、专有名词、数字，向量模型经常记不准）。
- 两路用 **RRF** 融合：$\text{score}=\sum_i\frac{1}{k+\text{rank}_i}$（$k$ 常取 60）。RRF 只用名次不用分数，避免两路分数不可比的问题。
- **结论：生产搜索几乎都是混合检索，只用其中一路都会有明显短板。** 这条同样适用于 RAG（见 [04 §7](04-llm.md)）。

### 9.5 相关性模型与点击模型

**相关性模型**：交互式 Cross-Encoder（query 和 doc 在每层交互，准，用于精排 top-N）vs 表示式双塔（可预计算，用于召回）—— 和 [07 §5](07-nlp-basics.md) 是同一套取舍。
相关性标注一般是 pointwise 多档（如 4 档：完全满足 / 基本满足 / 部分相关 / 不相关），由人工标注，是搜索团队最贵的资产。

**点击模型**：搜索的位置偏置比推荐更严重（用户从上往下扫）。
- **级联模型（Cascade Model）**：假设用户从上往下看，点击后停止 —— 于是"被点击项下方的展现"才算真正被看到，可用来估计观察概率。
- **DBN / PBM**：把"观察"和"吸引"拆成两个概率分别建模，比单纯位置特征更细。
- 用途：从点击日志里**反推无偏的相关性标签**，缓解 [§6.4](#64-位置偏置position-bias) 的位置偏置问题。

### 9.6 评价指标：NDCG（要能写公式）

$$\text{DCG@}k=\sum_{i=1}^{k}\frac{2^{rel_i}-1}{\log_2(i+1)},\qquad \text{NDCG@}k=\frac{\text{DCG@}k}{\text{IDCG@}k}$$

- 分子 $2^{rel}-1$：相关性档位越高收益指数增长，强调"把最相关的放最前"。
- 分母 $\log_2(i+1)$：位置折扣，排得越后价值越低。
- IDCG 是理想排序（按 rel 降序）的 DCG，用来归一化到 $[0,1]$，让不同 query 之间可比较、可平均。

**Q：搜索为什么用 NDCG 而推荐常用 AUC/GAUC？**
搜索有**多档人工相关性标签**，NDCG 能利用档位差异并且强调头部位置；
推荐一般只有 0/1 的隐式反馈，且关心的是"用户内部的排序"，所以用 GAUC。
**指标是被标签形态和业务目标共同决定的，不是随便挑的。**

## 10. 前沿趋势（能提一嘴会加分）

- **生成式推荐**：把推荐建模成序列生成任务。Meta 的 **HSTU / 生成式推荐范式**、Google 的 **TIGER**（用 RQ-VAE 把物品编成语义 ID，用生成模型直接生成下一个物品 ID），试图把 Scaling Law 引入推荐。
- **LLM + 推荐**：用 LLM 做冷启动的内容理解、生成解释、做特征增强、用作 reranker；难点是延迟和成本。
- **多模态内容理解**：短视频场景用视频/音频/文本的联合 Embedding 解决冷启动和内容同质化。
- **端上重排**：把部分重排逻辑下放到客户端，利用实时反馈。
- **全链路一致性**：召回-粗排-精排的联合训练/蒸馏。
