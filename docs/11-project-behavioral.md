# 11 · 项目深挖与行为面

> **八股答错扣分，项目讲崩直接挂。** 面试官通过项目判断三件事：这个项目是不是你做的、你有没有独立思考、你的技术深度到哪一层。

---

## 1. 项目深挖的固定套路

几乎所有面试官都按这条链路往下挖，每一层答不上就止步：

```
L1 你做了什么？        → 项目背景、你的角色、整体方案
L2 为什么这么做？      → 技术选型的理由、对比了哪些方案
L3 效果怎么样？        → 量化指标、baseline 对比、怎么验证的
L4 遇到什么问题？      → 具体的坑、怎么定位、怎么解决
L5 有什么不足？        → 现在回头看会怎么改进
L6 换个场景怎么办？    → 开放题，考察迁移能力
```

**关键认知**：L1-L3 是及格线（说明项目是真的），**L4-L5 才是拉开差距的地方**。能讲出一个具体的、有细节的坑，比讲一堆高大上的方法有用得多。

---

## 2. 每个项目要准备的"标准答案包"

对简历上的**每一个**项目，提前准备好这 10 个问题的答案：

1. **一句话说清这个项目做什么**（30 秒电梯陈述）。
2. **业务/研究背景**：为什么需要做这件事？不做会怎样？
3. **你负责哪部分**？团队几个人？（诚实，不要把别人的工作说成自己的）
4. **数据**：从哪来、多大、怎么清洗、标注怎么做、有什么质量问题。
5. **方法**：完整技术方案，能画出流程图。
6. **技术选型**：为什么选 A 不选 B？（**必被追问**，至少准备两个对比方案）
7. **指标**：离线指标是什么、baseline 多少、你做到多少、怎么验证不是过拟合。
8. **最大的困难**：一个具体的技术难点，从现象 → 定位 → 假设 → 验证 → 解决讲一遍。
9. **不足与改进**：诚实地说 1-2 个局限，并给出改进思路。
10. **如果数据量 ×100 / 要上线 / 延迟要求 10ms，你会怎么改**？

### 一个好的项目描述模板（STAR-R）

> **S 情境**：我们要给短视频推荐系统做冷启动优化，新发布视频前 24 小时的曝光效率比大盘低 40%。
> **T 任务**：我负责新视频的召回侧，目标是把新视频的 24 小时内 CTR 提升 10% 且不损害大盘。
> **A 行动**：我先分析发现新视频没有 ID Embedding，双塔召回给出的向量基本是随机的。我用视频的多模态内容特征（标题 BERT 向量 + 封面 CLIP 向量）训练了一个内容塔，用老视频的 ID Embedding 作为监督目标做蒸馏，让内容塔能"预测"出一个合理的初始 Embedding。上线时新视频先用内容塔的向量，累积 N 次曝光后平滑切换到学出来的 ID Embedding。
> **R 结果**：离线新视频召回 Recall@100 从 0.21 提到 0.34，线上 AB 新视频 24 小时 CTR +13%，大盘 CTR 持平（-0.1%，不显著）。
> **R 反思**：切换阈值 N 是拍的（100 次曝光），事后看应该按置信度动态切换；另外内容塔没利用视频帧序列信息，只用了封面，这块还有空间。

**注意这段话里的几个加分点**：有具体数字、有归因分析（"我先分析发现…"）、有工程落地细节（平滑切换）、有诚实的不足。

## 3. 分方向的常见追问

### 3.1 推荐/广告类项目

- 你的样本是怎么构造的？正负样本比例？负样本从哪来？
- 特征有多少维？有没有做特征重要性分析？哪些特征最有用？
- 有没有特征穿越？你怎么确认没有？
- 离线 AUC 提升了多少？线上呢？如果不一致你怎么排查？
- AB 实验怎么做的？流量多大？跑了多久？置信度算了吗？
- 模型多久更新一次？增量训练还是全量？
- 线上推理延迟多少？QPS 多少？
- 如果让你把这个模型的效果再提 5%，你会先做什么？

### 3.2 LLM 类项目

- 数据是怎么构造的？多少条？质量怎么保证？有没有去重和去污染？
- 为什么选这个 base model？试过别的吗？
- 用 LoRA 还是全参？r 取多少？加在哪些模块？为什么？
- 学习率、batch size、训练多少 step？怎么定的？
- 怎么评测的？有没有人工评？评测集怎么构建的？防污染了吗？
- 有没有出现灾难性遗忘？怎么发现和缓解的？
- 推理性能怎么样？做了什么优化？
- 如果模型产生幻觉/不听指令，你怎么定位是数据问题还是训练问题？

### 3.3 CV 类项目

- 数据集多大？标注质量如何？类别分布均衡吗？
- 用了哪些数据增强？为什么是这些？
- backbone 怎么选的？有没有对比实验？
- 小目标/遮挡/长尾怎么处理的？
- 推理速度多少 FPS？在什么硬件上？做了什么加速？
- badcase 分析做了吗？主要错在哪类样本？

### 3.4 论文/竞赛类项目

- 你的创新点相比 baseline 到底改了什么？
- 消融实验做了吗？哪个模块贡献最大？
- 这个方法的失效场景是什么？
- 竞赛的 trick 有多少是能落地到实际业务的？

## 4. 简历怎么写项目

**反例**：
> 使用深度学习方法进行推荐算法研究，搭建了基于 Transformer 的推荐模型，取得了良好的效果。

问题：没有具体方法、没有量化结果、"良好的效果"等于没说。

**正例**：
> **短视频冷启动召回优化** | 推荐算法实习 | 2025.06–2025.09
> - 定位新视频 ID Embedding 冷启问题，设计多模态内容塔（BERT 标题 + CLIP 封面）蒸馏老视频 ID Embedding，解决新视频召回向量无意义的问题
> - 设计基于曝光量的平滑切换策略，新视频召回 **Recall@100 从 0.21 提升至 0.34**
> - 线上 AB 实验（10% 流量，7 天）：**新视频 24h CTR +13%**，大盘 CTR 持平

三条 bullet 对应：**做了什么方法（技术含量）→ 解决什么问题（动机）→ 量化收益（结果）**。

**没有量化指标怎么办？**
- 用相对提升代替绝对值："相比 baseline 提升 12%"。
- 用工程指标："推理延迟从 80ms 降到 23ms"、"训练时间缩短 40%"。
- 用规模描述："处理 500 万条数据"、"支撑日均 100 万次调用"。
- 用定性但具体的描述："解决了长尾类别召回为 0 的问题"。

## 5. 行为面高频题（附回答思路）

| 问题 | 回答框架 | 要避开的坑 |
|---|---|---|
| **自我介绍** | 30-60 秒：我是谁 + 我的技术标签 + 最相关的一段经历 + 为什么投这个岗 | 不要念简历、不要超过 2 分钟 |
| **最有成就感的项目** | 选技术深度最高、你主导性最强的那个，用 STAR-R | 不要选你只打了辅助的项目 |
| **遇到的最大困难** | 必须是**技术困难**，讲清定位过程 | 不要说"没遇到过困难"、不要讲人际矛盾 |
| **和队友有分歧怎么办** | 用数据/实验说话 → 讲一个真实案例 → 结果 | 不要塑造"我一直是对的"的形象 |
| **你的缺点** | 说一个真实的、正在改进的、与岗位无致命冲突的 | 不要说"我太追求完美了" |
| **为什么选我们公司/这个组** | 具体到业务和技术栈，说明你做过功课 | 不要说"贵公司平台大" |
| **职业规划** | 1-2 年打好某方向的基础，3-5 年成为某领域能独当一面的人 | 不要说想创业、想转管理 |
| **手上有几个 offer** | 诚实回答，表达对本岗位的真实兴趣和评估维度 | 不要虚构 offer 抬价 |
| **能实习多久** | 诚实。校招实习通常要求 3 个月以上、每周 4-5 天 | 不要含糊其辞 |

### 关于"最大的困难"

这题的标准结构：
1. **现象**：训练 loss 正常但线上效果比离线差了 8 个点。
2. **排查**：先怀疑分布偏移 → 对比线上线下特征分布，发现某个统计特征的均值差了一个量级。
3. **定位**：离线用了全量数据算的窗口统计，线上是实时增量算的，两边窗口口径不一致。
4. **解决**：改成用线上落盘的特征快照做训练，从根本上保证一致。
5. **结果 + 沉淀**：线上恢复到离线水平，之后我们把特征一致性检查加进了上线 checklist。

**第 5 步的"沉淀"很重要** —— 说明你不只是解决了一个 bug，而是形成了方法论。

## 6. 反问环节（不要说"没有问题"）

反问是**双向选择**的机会，也是最后一次加分机会。分对象准备：

**问技术面试官（一面二面）**：
- 这个组目前主要在做什么方向？技术栈是什么？
- 我这个岗位入职后大概会先接触哪部分工作？
- 组里对校招生的培养机制是怎样的？有 mentor 吗？
- （加分）我刚才在 XX 问题上的回答，您觉得有什么可以改进的方向吗？—— **展现学习意愿，而且能得到真实反馈**

**问主管（三面/交叉面）**：
- 这个组在部门/公司里的定位和长期规划是什么？
- 团队的技术氛围怎么样？有论文发表/开源的机会吗？
- 您对新人一年内的期待是什么样的？

**问 HR**：
- 转正/晋升的机制是怎样的？
- 团队规模和组成？
- 后续流程和时间节奏？

**避免问**：加班多不多（换成"团队的工作节奏是怎样的"）、工资多少（HR 面再谈）、能不能给我调组。

## 7. 面试当天的实操建议

- **技术面前**：把简历打印出来放手边，标注每个项目的关键数字。
- **手撕代码时**：先问清楚输入输出和边界，写完主动跑一个例子。卡住了主动说"我先说一下我的思路，可能需要一点提示"，比沉默 5 分钟强得多。
- **不会的题**：诚实说不会，但要说"我了解相关的 XX，我猜可能是这样…"，展现推理能力。**绝对不要编。** 面试官对自己领域的问题一听就知道你在编。
- **被 challenge 时**：先认真听完，如果对方说得对就承认并接上"确实，我之前没考虑到这个，那这样的话应该…"；如果你有把握，礼貌地摆出你的理由。**盲目坚持和盲目认错都扣分。**
- **面完当天**：复盘写下所有问题和自己的回答，标记答得不好的，当天补上。**这个复盘的价值远大于再刷 10 道题。**

## 8. 没有拿得出手的项目怎么办？

校招常见困境。按性价比排序：

1. **把课程项目/竞赛做深**：Kaggle / 天池的一个 top 10% 方案，把特征工程和模型选型讲清楚，比三个浅项目强。
2. **复现一篇论文并做改进**：不用是 SOTA，关键是你能讲清楚原论文的动机、你复现时遇到的差异、你做了什么改动及其效果。
3. **做一个端到端的小系统**：比如自己爬数据 + 训模型 + 做成 API + 部署上线。**"端到端"这三个字在面试里很值钱**，因为它证明你懂工程。
4. **参与开源**：给主流框架提 PR，哪怕是文档和小 bugfix，也是可验证的贡献。
5. **实习 > 一切**：如果还有时间，优先去拿一段实习，日常实习的门槛远低于正式校招。

**共同要求**：无论哪种，都要有 **可量化的结果** 和 **你自己的思考痕迹**。
