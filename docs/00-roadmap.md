# 00 · 复习路线图与时间规划

> 面向 2026/2027 届算法岗校招与实习。目标：在有限时间内把"能被问到的东西"尽量覆盖，把"高频必问"打扎实。

---

## 0. 关于本手册（先读这一节）

### 内容是怎么来的

本手册由 AI 依据公开技术资料整理成稿，**不含任何公司内部信息或面试真题原文**。
它的定位是**结构化的复习索引**：帮你快速定位"该会什么、该答到什么深度、会被往哪追问"，
而不是替代论文和官方文档。

### 三种可信度，请区别对待

| 标记 | 含义 | 怎么对待 |
|---|---|---|
| 无标记 | 领域内的共识性结论、可推导的数学事实 | 可直接用 |
| `〔来源〕` | 出自某篇具体论文/官方文档，章末「延伸阅读」列了出处 | 引用时请核对原文的适用条件 |
| `（主观判断）` | 作者对考察频率、优先级、经验参数的估计，**没有统计支撑** | 当作参考排序，不要当事实复述给面试官 |

**特别说明**：各章开头「本章高频考点」表格里的 ★ 星级，以及各处的"高频/必问"字样，
**全部是主观判断**。它们反映的是常见面经里的印象分布，不是任何统计结果。
不同公司、不同组的差异很大，请以你实际投递的岗位为准。

### 时效性

深度学习和大模型领域半年就会变。每章开头标了 `更新于` 和 `时效` 两个字段：

- `时效：慢` —— 数学、经典机器学习、算法题，几年内不会变
- `时效：中` —— 深度学习基础、CV、NLP、工程实践
- `时效：快` —— 大模型、推荐前沿，**建议面试前再对一遍最新进展**

### 这本手册最欠缺什么

诚实地说三条：

1. **深度是索引级，不是教程级。** 平均每章 5 千字要覆盖一个大领域，被追问到第三层会不够用。
   遇到你要深挖的点，请按章末「延伸阅读」去看原文。
2. **没有真实面经。** 所有题目来自公开资料的整理，不是任何人实际被问到的记录。
3. **参考文献只给了论文标题和年份，没给链接**，因为成稿环境无法联网核验 —— 与其给可能失效或指错的
   链接，不如给可搜索的准确标题。

**最好的用法**：把它当脚手架，每面完一场就把你真实被问到的题和你的回答补进 `data/questions.json`。
半年后这里面有 200 道你亲身遇到的题，那才是别人抄不走的东西。

## 1. 先搞清楚"算法岗"到底考什么

国内算法岗面试基本是五块拼图，权重因公司/组而异。
**下表的百分比是主观估计**（基于公开面经的印象分布），用来排优先级，不是统计数据：

| 模块 | 校招权重（主观） | 说明 |
|---|---|---|
| 手撕代码 | 30% | LeetCode 中等为主 + 手写 ML/DL 组件（attention、KMeans、NMS、AUC） |
| 机器学习/深度学习八股 | 30% | 概念推导 + 为什么，不是背名词 |
| 方向专精（LLM / 推搜广 / CV） | 20% | 对应组的技术栈，决定你能不能进这个组 |
| 项目深挖 | 15% | 简历上每一行都可能被追到底 |
| 数学 + 概率题 + 智力题 | 5% | 部分公司（尤其量化、大厂 SP）会考 |

> 上表没单列因果推断和强化学习，因为它们**按方向计入"方向专精"**：
> 投推荐/广告/增长的会被问 Uplift 和实验设计（[14](14-causal-uplift.md)），
> 投大模型的会被问 PPO 和 RLHF 的机制（[15](15-rl-basics.md)）。

**一个关键认知**：校招算法岗的淘汰主要发生在两处 —— 手撕代码写不出来（直接挂），项目讲不明白（说明简历是编的）。八股答不全通常只是扣分。所以优先级是：**代码 ≥ 项目 > 八股 > 方向前沿**。

## 2. 三种时间预算下的复习路径

### A. 3 个月（时间充裕，建议路径）

| 周次 | 主线 | 每日代码 |
|---|---|---|
| W1–W2 | 数学基础 + 经典 ML（[01](01-math-basics.md), [02](02-machine-learning.md)） | LeetCode 数组/双指针/二分，3 题/天 |
| W3–W4 | 深度学习基础（[03](03-deep-learning.md)） | 链表/栈队列/哈希，3 题/天 |
| W5–W6 | 方向专精第一轮（[04](04-llm.md) 或 [05](05-recsys-ads.md) / [06](06-cv-multimodal.md)） | 二叉树/递归/回溯，3 题/天 |
| W7–W8 | 手写代码专项（[09](09-coding-ml-scratch.md)）+ 工程（[10](10-engineering.md)）+ SQL（[12](12-sql-bigdata.md)） | DP + 图，2 题/天 |
| W9–W10 | 项目梳理与 STAR 化（[13](13-project-behavioral.md)）+ 系统设计（[11](11-system-design.md)） | 高频题二刷，2 题/天 |
| W10 补充 | 按方向选修：LLM 方向补 [15 强化学习](15-rl-basics.md)，推搜广/增长方向补 [14 因果推断](14-causal-uplift.md) | 同上 |
| W11–W12 | 模拟面试 + 题库自测（[16](16-question-bank.md)） | 随机抽题限时写，2 题/天 |

### B. 1 个月（秋招已开，紧急）

- 第 1 周：[16-question-bank](16-question-bank.md) 全过一遍，标记不会的 → 只补标记项。
- 第 2 周：LeetCode Hot 100 + [09](09-coding-ml-scratch.md) 手写题全部默写一遍。
- 第 3 周：项目 STAR 化 + 方向专精突击（只看你投的组对应的那一章）。
- 第 4 周：每天一场模拟面（找人/找 AI），复盘卡壳点。

### C. 1 周（明天就面了）

1. [16-question-bank](16-question-bank.md) 里"必答"标记 ★★★ 的题，全部能口述。
2. [09](09-coding-ml-scratch.md) 中的 **手写 self-attention / 手写 KMeans / 手写 AUC / 手写 NMS**，默写到不看答案。
3. 把简历上每个项目写成 STAR 稿，念熟（[13](13-project-behavioral.md)）。
4. 面试当天早上：过一遍 [02](02-machine-learning.md) 和 [03](03-deep-learning.md) 的"一句话速记"表格。

## 3. 怎么用这本手册

- **不要顺序读完再开始刷题。** 代码和八股必须并行，代码是每天的肌肉记忆。
- 每章开头有「本章高频考点」表格，先看表格判断自己会不会，会的直接跳过。
- 每个知识点尽量以「**问题 → 答案骨架 → 追问**」的形式组织，因为面试官就是这么问的。追问部分是拉开差距的地方。
- 章末的「自测清单」勾不满就别翻篇。
- 网页版（`site/`，构建后本地 `npm run dev` 打开）支持全书搜索、随机抽题和进度追踪，适合做自测。

## 4. 简历与投递节奏（校招）

- **提前批（6–8 月）**：机会最多、要求最高、挂了通常不影响正式批。一定要投，当练兵。
- **正式批（9–11 月）**：主战场，海投但要分批 —— 先投练手公司，攒面经，再冲目标公司。
- **补录/春招（次年 2–4 月）**：捡漏窗口。

简历一页纸，结构固定：教育经历 → 实习 → 项目 → 竞赛/论文 → 技能。
每个项目 3–4 条 bullet，每条遵循「做了什么方法 → 解决什么问题 → 带来什么量化收益」。没有量化收益就写对比 baseline 的相对提升。

## 5. 常见误区

| 误区 | 纠正 |
|---|---|
| 疯狂刷 LeetCode Hard | 校招算法岗以中等题为主，Hard 只在少数公司出现（主观判断）。把中等题写到 15 分钟内 bug-free 更值钱 |
| 只背八股不推导 | "为什么 BN 在 NLP 里不好用" 这类追问一问就穿帮 |
| 简历写没做过的项目 | 面试官深挖三层必挂，且大厂会记录 |
| 只准备一个方向 | 校招常被调剂组，通用 ML/DL 基础必须扎实 |
| 忽略工程能力 | 算法岗的实际工作里工程占比很高，问 PyTorch/分布式/部署是常态 |
